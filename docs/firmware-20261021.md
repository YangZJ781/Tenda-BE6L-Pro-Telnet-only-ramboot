## 提取与交叉核对

原始 ZIP 中的厂商 BIN 已单独提取、记录 SHA-256，并经原厂升级接口接受。分析时先在原厂系统 RAM 中运行 `decry_firm`，取回解密结果；四版 rootfs 均从偏移 4194368 开始，使用 `nice` 标记和 Tenda 改写的 XZ 压缩块。

只更改 `nice` 为 `hsqs` 仍不足以解包。本轮读取器解析元数据及片段表，跳过厂商 XZ 外层头部，直接解码 LZMA2 内容。该方式不核验改写的 XZ 外层校验码，因此另以镜像 SHA-256、传输 MD5、运行设备导出文件和真实 Telnet 登录交叉核对；不能将解码成功本身视作厂商签名验证。

读取器先用既有 .51 RootFS 备份验证，所得 `cnsl_safe` 与此前设备导出逐字节相同。四版 `cnsl_safe` 均为 5296 字节；其 `.text` 段均为 1384 字节，与 .62 逐字节一致，代码段 SHA-256 为 `ba7a5f9124bc61939c03a799ddd05733bcd75e3ca516897cfeaec3d329dc8cc1`。将各自种子字符串替换为 .62 的种子后，整个 5296 字节程序也与 .62 完全一致，进一步确认变化仅为种子。

## 验证边界与交付

- 四版均通过管理员鉴权后的 `/goform/telnet` 开启服务，派生密码取得 `Uid: 0 0 0 0`；未对四版执行匿名接口绕过测试。
- 四版均备份 12 项原厂 MTD；长度、设备 MD5、本地 MD5 / SHA-256 一致。从活动 RootFS 的实际 BIN 再提取程序，与运行设备和离线镜像一致。备份含相互重叠的 KernelFS / RootFS 别名，不包含 OOB / BMT，配置数据未冻结，未作为公共发布附件。
- 四版均用相同的单文件 PS1 完成全流程，自动识别版本、Telnet root、默认 30 MiB 临时盘、六文件校验、kexec 装载与切换，以及从网络确认 `rootfs_type=initramfs`、Linux 6.18.52。RAM 启动过程不访问 TTL、不写闪存。
- 每次启动后先正常重启回原厂，再进行下一版网页升级。TTL 仅被研究用升级程序被动记录，不参与 ramboot。
- 最后已恢复原厂 `V16.03.60.62_cn` 并重新验证网页版本、Telnet root。无线仍由内嵌临时 DTB 禁用。
- Windows PowerShell 5.1 / PowerShell 7 的七版选择、固定密码夹具、版本不符/未知版本拒绝、RAM 范围和内置传输代码检查均通过。
- 本轮 .16 / .51 / .62 的完整启动记录沿用此前结果；当前构建的完整启动实测范围是新增四版，.62 另做恢复后的检查。
